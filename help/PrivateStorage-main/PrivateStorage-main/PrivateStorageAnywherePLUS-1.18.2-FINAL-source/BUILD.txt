================================================================================
 Private Storage Anywhere PLUS - 1.18.2 patcher, build instructions
================================================================================

 This archive contains the patcher and the technical notes. It does NOT contain
 the mod itself.

 The original mod is Stevi's PrivateStorageAnywherePLUS v1.5.10 (Nexus Mods,
 Crimson Desert, mod 388). Their permissions do not allow their file to be
 redistributed, so you supply your own copy - download v1.5.10 from Nexus and
 point the script at the .asi inside it.

   https://www.nexusmods.com/crimsondesert/mods/388

 CONTENTS

 FINDINGS-1.18.2-MODESTATE.md              full technical record, sections 1-56

 BUILD.txt                                 this file


--------------------------------------------------------------------------------
 REQUIREMENTS
--------------------------------------------------------------------------------

 Python 3.10 or newer, and pefile:

   pip install pefile

 That is the only dependency the patcher itself needs. (The findings document
 references capstone, which was used for disassembly during analysis - it is
 not needed to build.)


--------------------------------------------------------------------------------
 BUILDING
--------------------------------------------------------------------------------

   python patch_private_storage_1182_modestate.py <pristine.asi> <output.asi>

 For example:

   python patch_private_storage_1182_modestate.py ^
       PrivateStorageAnywhere.asi ^
       PrivateStorageAnywhere-1.18.2.asi

 The script refuses to run on anything but the exact v1.5.10 binary:

   input   SHA-256  4F514298B2BC5DB7E804B0166AD2269BAE97A414F7DAE425A0F736CDA7F56F3E
                    256,000 bytes

 and a correct build produces:

   output  SHA-256  A7F7D38169250E1FE1D570613369022CA4933721943E5C113687B7F9D0AA51EE
                    264,192 bytes

 If your output hash matches, you have byte-for-byte the build that was tested.

 On success it prints the input hash, the derived field layout, the code-cave
 extents, the output hash and the byte count. Anything else is a failure - the
 script raises rather than continuing.


--------------------------------------------------------------------------------
 HOW IT WORKS, BRIEFLY
--------------------------------------------------------------------------------

 Every change is applied to the pristine binary in one pass. Before each write
 the script checks the exact bytes it expects to find at that address, so a
 mismatch stops the build instead of silently corrupting the file. There is no
 hand-editing anywhere in the chain, and the build is reproducible.

 The 1.18.2 fixes are in-place edits to existing code. The optional Private
 Storage capacity feature is new code, and rather than squeeze it into the
 480 bytes of executable slack in .text, the script appends two sections:

   .pstext   RVA 0x46000   4 KB   code, read + execute
   .psdata   RVA 0x47000   4 KB   data, read + write

 They are separate deliberately: a single writable-and-executable section trips
 the "packed executable" heuristic in PE scanners, and the feature needs
 exactly four writable bytes. PE header offsets are derived from e_lfanew and
 cross-checked against pefile before anything is written - an early draft
 hardcoded that offset, got it wrong by 0x18, and quietly corrupted the
 optional header. The differential check against the known-good baseline caught
 it, which is why that check is in the verification list below.


--------------------------------------------------------------------------------
 VERIFYING A BUILD
--------------------------------------------------------------------------------

 Beyond the output hash, the properties worth asserting against a known-good
 baseline (the 1.18.2 build without the storage-capacity feature):

 - Inside the original 256,000 bytes, the only differences are two PE header
   fields (NumberOfSections, SizeOfImage), the two appended section headers,
   two call displacements, and the build tag byte.
 - The 480-byte .text cave at 0x27A20 is all zeros - the feature does not live
   there.
 - Both crash-fix NOP sites, the housing expansion path, the readiness gate and
   both spinlock releases are byte-identical.
 - The exception directory still holds 589 entries.
 - pefile parses the output with no warnings beyond the two pre-existing
   UNWIND_INFO ones that the original file also produces.


--------------------------------------------------------------------------------
 READING THE FINDINGS
--------------------------------------------------------------------------------

 FINDINGS-1.18.2-MODESTATE.md is the working record, in order, including the
 attempts that were wrong and what disproved them. If you only want the
 conclusions:

   sections 1-30    the mode-state breakage and the two crashes
   section  31-34   the housing 10 -> 1000 expansion
   sections 37-46   locating the Private Storage record
   sections 47-56   the capacity feature: the total formula, the container
                    list, the index-vs-key mistake, and the restore path

 Game addresses in that document are RVAs on base 0x140000000; ASI addresses
 are RVAs on base 0x180000000.
