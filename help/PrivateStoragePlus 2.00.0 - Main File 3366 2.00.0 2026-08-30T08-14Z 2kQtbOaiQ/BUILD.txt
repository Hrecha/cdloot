================================================================================
  PrivateStorageAnywherePLUS - Crimson Desert 2.00
  Reproducing this build
================================================================================

The release ASI is deterministic: the same pristine input plus the same game
executable always produces the same bytes. Verify it yourself rather than
trusting the hash in the README.


--------------------------------------------------------------------------------
  WHAT YOU NEED
--------------------------------------------------------------------------------

  1. The pristine Private Storage Anywhere v1.5.10 ASI, unmodified:
       SHA-256  4F514298B2BC5DB7E804B0166AD2269BAE97A414F7DAE425A0F736CDA7F56F3E
     The patcher refuses to run on anything else.

  2. Crimson Desert 2.00's bin64\CrimsonDesert.exe.
       SizeOfImage 0x16499000
     Every game-side address is derived from this file at build time. Nothing
     is hardcoded, so the exe you build against must be the one you play on.

  3. Python 3.11+ with the packages in requirements.txt:
       capstone, pefile, py7zr


--------------------------------------------------------------------------------
  BUILD
--------------------------------------------------------------------------------

    python tools/patch_private_storage_1182_modestate.py \
        original/PrivateStorageAnywhere.asi \
        patched/PrivateStorageAnywhere-2.00.AX-modeoffset.asi \
        "<game>/bin64/CrimsonDesert.exe"

Expected output on Crimson Desert 2.00:

    derived  CampWareHouse=0x501C6B8 NameToKey=0x1E37F50
             ResolveActor=0x75BF90 ModeSwitch=0x530E20
    derived  ingame-mode=4 store-sub=5
    layout   mode=0x28 sub=0x29 flags=0x31 subtypes=0x38 dirty=0x5B
    output_sha256=c2b9848f33a3822532c563c31965f4dff74b0d02a369ae7626d3e43056c49840

If any anchor cannot be found, is ambiguous, or the derived layout fails its
internal spacing checks, the build stops with an error instead of producing a
file. That is deliberate: a build that emits a plausible-looking ASI against a
game version it does not understand is how the 1.18.2 release came to crash on
2.00.


--------------------------------------------------------------------------------
  VALIDATE
--------------------------------------------------------------------------------

    python tools/validate_aw.py \
        patched/PrivateStorageAnywhere-2.00.AX-modeoffset.asi \
        "<game>/bin64/CrimsonDesert.exe" \
        --pristine original/PrivateStorageAnywhere.asi

Add --listing for a full disassembly of the appended code section.

The name is historical - it was written for the AW build - but it validates the
whole AT-through-AX lineage and should be run on every build. It disassembles
the produced file rather than trusting the emitter, and checks:

  * section layout, characteristics, SizeOfImage, 589 exception-directory
    entries, and no pefile warning beyond the two the pristine input already
    carries;
  * no sub/add rsp with a negative immediate - an imm8 sign-extension bug that
    shipped once and was caught in review;
  * the capture stub pushes nothing, re-issues the game's displaced prologue
    bytes verbatim, and returns to the correct address;
  * the probe reads the DERIVED layout offsets, not a second hardcoded copy,
    and every byte it reads is readability-guarded;
  * the vararg marshalling map, exactly;
  * the game's ModeSwitch prologue still matches the bytes the hook expects;
  * no stale 1.18.2 address survives and every 2.00 target is present.

Add --vs <earlier.asi> to list every changed byte inside the original 256 KB
against a previous build.


--------------------------------------------------------------------------------
  RE-DERIVE THE LAYOUT ON ITS OWN
--------------------------------------------------------------------------------

    python tools/derive_modestate.py "<game>/bin64/CrimsonDesert.exe"

Prints the UI mode-tag pool, the two jump tables that give the in-game mode (4)
and the store sub-mode (5), the located ModeSwitch, the five field offsets, and
the four spacing checks. Useful first step when a game patch breaks things.


--------------------------------------------------------------------------------
  ON WINDOWS
--------------------------------------------------------------------------------

If you are using a vendored package directory rather than an installed
environment, put both it and tools/ on the path - note the ';' separator:

    PYTHONPATH=".tools;tools" python tools/...


--------------------------------------------------------------------------------
  WHAT THE PATCH ACTUALLY DOES TO THE ASI
--------------------------------------------------------------------------------

Two sections are appended: .pstext (code, read+execute) and .psdata (data,
read+write). Keeping them separate rather than using one read-write-execute
section avoids the packed-executable heuristic in PE scanners.

Inside the original 256 KB the changes are small and enumerable: the legacy
layout resolver is replaced by a stub that publishes the derived offsets, the
mode-object helper becomes a jump into .pstext, two call sites are re-pointed
at a wrapper, one 10-byte diagnostic hook is installed on the refusal path, and
the build tag is rewritten. --vs prints the exact list.

At runtime the mod installs one 8-byte hook into the game's mode-switch
function. It is a single aligned qword store, which x86-64 performs atomically,
so a function that runs every frame can be patched without a window in which it
decodes as garbage. All fifteen prologue bytes are re-checked immediately
before the write; if they do not match, nothing is written and the mod falls
back to its previous behaviour.
