# Crimson Desert AutoLoot —— 版本适配流程

> 新游戏版本出来时的 CT 适配步骤。配套文件:
> - `CrimsonDesert_AutoLoot_v7.0.CT` —— 主表
> - `health_check.lua` —— 一键体检(AOB 状态 + 偏移自检 + desc 自检)
> - `dump_event_descriptors.lua` —— dump 全部事件 desc ID→类名

---

## 按顺序排查

### 第 0 步:尝试激活主表(分流点)

先**原样加载并激活主表**。AOB 扫描会在函数地址变化时自动重定位,大概率能直接用。
以"能否激活"分流:

- **激活成功、功能正常** → 收工。若功能异常(如能拾取但行为不对)→ 多半是 desc 变了,跳第 2 步。
- **激活失败**(报某个 AOB not found) → 跳第 1 步跑体检看 [A]。

### 第 1 步:跑健康检查脚本(定位问题范围)

运行时机取决于第 0 步结果:

- **激活失败时**:此时主表没装 hook,直接跑 `health_check.lua` 看 **[A]** ——
  哪些 AOB ❌失配就是要修的(这种场景 [A] 最干净,无 hook 干扰;[B] 提示缺上下文属正常)。
- **激活成功时**:进可交互状态后跑,重点看 **[B]/[C]** ——
  相机/area hook 点的原始字节已被跳转桩覆盖,[A] 会把这两项标"✅已hook"(不是错)。

报告三段:
- **[A]** 12 个 AOB 匹配数(✅唯一 / ❌失配 / ⚠️多匹配 / ✅已hook)
- **[B]** 结构偏移活体验证(实体 EID 格式、指针规范、comp+0x2C8 取值集合、intermediate 链)
- **[C]** desc 表解析,按稳定类名报出 Take/Search/Catch 当前 desc_id

红的那几项就是要修的,精准处理(AOB→第3步,desc→第2步,偏移→第4步)。

### 第 2 步:desc ID 变了 → 跑 dump 脚本

症状:能拾取但行为异常,或体检 desc 项报警。
desc ID 每版可能 +1/+2(协议值,引擎按注册顺序分配)。运行 `dump_event_descriptors.lua`,
按**稳定类名**查新值(类名是源码符号,跨版本不变):

| 交互 | 类名(搜这个) | 1573 值(参考) |
| --- | --- | --- |
| 拾取/采集 | `ProcessPickUpItemOnceTimer` | 0x0809 |
| 搜刮尸体 | `ProcessLootingDeadDropOnceTimer` | 0x07E8 |
| 捕捉昆虫 | `PushCharacterToInventoryOnceTimer` | 0x0800 |

把新值填进 CT 对应的 `mov edx, XXXX` 和 buffer 常量(CT 内 do_search/do_take/do_catch
及 area 路径,每类两处:相机一处 + 区域一处)。

### 第 3 步:AOB 失配 → x64dbg 反汇编重推

每个 AOB 对应一个"锚点函数"或代码点。通用重推手法:

**手法 A:靠字符串/常量定位函数**
锚点函数常引用独特字符串。x64dbg 里右键 → Search for → String references:
- 相机 UI 函数:`InteractionRightRowCoin` / `KeyGuideButtonInteraction` / `KeyGuideButtonWidget`
- desc 系统:RTTI 名如 `ProcessPickUpItemOnceTimer`(dump 输出里有对象地址)

**手法 B:靠"旧 AOB 的稳定子串"重新定位**
失配通常只是局部字节变了。把旧 AOB 砍成前半段更短的子串重新搜:
- x64dbg 内存搜索短模式,看命中数
- 候选在反汇编窗口对照下方"锚点说明"确认
- 确认后把新的完整字节序列复制出来做成新 AOB

#### 各 AOB 锚点说明(重推时对照)

| AOB | 锚点 = 什么代码 | 重推识别特征 |
| --- | --- | --- |
| 相机 hook | 相机交互 UI 更新函数里的"类型字节加载+vtable调用" | `movzx r??, byte ptr [rax+66]; mov rax,[r??]; mov rcx,r??; call qword ptr [rax+108]`。前面紧邻 `lea rcx,[r13+10]; call`。在引用 InteractionRightRowCoin 的函数内。|
| merge | 同一函数后段,两次解引用 | `mov r??,[r??+D0]; mov rax,[r??+D0]`。是 cave skip 路径跳回的目标。|
| GetWorldPos | 世界坐标 getter 函数开头 | `40 53 48 83 EC 50 48 8B 41 68 48 8B DA` 后跟 `mov r??,[r??+1A0]` 再 `vmovups xmm,[r??+98]`。纯函数,读 [arg+0x68]→[+0x1A0]。|
| area hook | 区域逐实体遍历函数入口 | 长 push 序列 `55 41 54 41 55 41 56 41 57 48 8B EC 48 83 EC 50` + AVX `C5 F8 29 74 24 40`。用 ScopeAttacher<ClientActor>,读 [rcx+0x110] 实体数组、[rcx+0x20] 玩家。|
| STEAL_BYPASS | 物品 Take 处理函数里的偷窃门 | `call <偷窃判定>; test al,al; jz; mov bl,2`。判定函数 1573=sub_142007490,有 6 个调用者。|
| STEAL_BYPASS2 | 植物 Gather 路径偷窃门 | `call <同一偷窃判定>; test al,al; jnz; xor bl,bl`。短跳 jnz(2字节)。|
| TLS init / desc lookup / event alloc / event enqueue / hash lookup | 事件系统底层函数 | 稳定的运行时库函数,极少变。失配多半是整体大改,届时再深查。|
| DESC_MASK/QUEUE resolver | 事件构造里解析两个全局的代码 | `call; mov r8d,[rip+x]; movzx edx,..; call; mov r12,[rip+y]`。脚本从命中点 +5/+22 用 RIP 解析全局地址。|

#### 重推后必须验证唯一性
新 AOB 抄好后,CE 用 `AOBScan` 看 Count,或 x64dbg 内存搜索看命中数。
> ⚠️ 不唯一(多匹配)会绑错地址 → 崩溃。务必加长特征直到唯一。

#### 寄存器重排陷阱(1573 相机 hook 的教训)
有时 AOB 能匹配但**寄存器换了**(如 context 从 r14 变 rsi、类型字节从 esi 变 r15d)。
cave 内重放原指令的代码要跟着改寄存器。改 CT 时同步更新:
- `not_autoloot` 重放块的寄存器
- cave 入口对 context 的捕获(v7.0 用 `mov r14, rsi` 把 context 存进 cave 不破坏的 r14)
- 偷取长度(指令字节数变了 → readmem 长度、跳转桩 NOP 数、ret 偏移都要改)

### 第 4 步:结构偏移漂移 → 体检探针会报

结构偏移很少在大版本间动(687→978 动过一次 +8,978→1573 没动)。
体检脚本内嵌活体探针:遍历真实实体,验证每个偏移取到的值是否合理
(实体 EID 是否 0xB01xxxxx 格式、指针是否规范、comp+0x2C8 取值是否在已知集合 {1,9,F,11,16})。
探针报"取值异常"时,用 x64dbg 在一个已知实体上手动试探邻近偏移(±8 范围)找回正确值。
